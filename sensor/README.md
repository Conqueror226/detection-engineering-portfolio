# ECS Network Telemetry Sensor

A Scapy-based sensor that captures (or replays) packets, aggregates them into
flows, and emits **ECS network events** as NDJSON. It is a *telemetry producer
only* — it does not decide what is malicious. Detection and correlation live in
`../detections`, which join these network events with Windows authentication and
process events.

This is the network-evidence layer of the portfolio's full-chain signature:
**network connection → authenticated pivot → process execution**.

## Usage

```bash
# Offline replay (no privileges) — used by CI and tests
python sensor/sensor.py --pcap sensor/fixtures/lateral_movement.pcap

# Live capture (requires root / Administrator for raw sockets)
sudo python sensor/sensor.py --iface eth0 --out network.ndjson
```

Options: `--pcap FILE` | `--iface IFACE` (mutually exclusive), `--out FILE`
(default stdout), `--host-name NAME`, `--count N` (live: stop after N packets).

## Output (ECS)

One event per flow, keyed by `(source.ip, destination.ip, transport, destination.port)`:

```json
{
  "@timestamp": "...",
  "event": { "category": ["network"], "type": ["connection"], "action": "network_flow" },
  "source": { "ip": "10.20.4.51", "port": 49712 },
  "destination": { "ip": "10.20.4.60", "port": 3389 },
  "network": { "transport": "tcp", "protocol": "rdp", "packets": 6, "bytes": 804 },
  "host": { "name": "WS-FIN-07" },
  "observer": { "type": "scapy-ecs-sensor" }
}
```

`network.protocol` is a best-effort label from the destination port
(rdp/smb/kerberos/dns/http/https/ldap/…).

## Fixtures

`fixtures/*.pcap` are synthetic, generated by `generate_fixtures.py` (committed
so the pcaps are reproducible, not opaque):

| Fixture | Scenario | Feeds |
|---|---|---|
| `lateral_movement.pcap` | RDP (tcp/3389) connection, attacker → target | authenticated-pivot detection |
| `port_scan.pcap` | one source → 25 distinct ports on one host | T1046 discovery detection |
| `benign.pcap` | ordinary HTTPS + DNS | negative case |

Regenerate with `python sensor/generate_fixtures.py`.

## Design notes

- **Offline-first for testability.** pcap-replay needs no privileges, so the
  sensor runs in CI; live capture is the same code path with a different source.
- **Flow aggregation**, not per-packet output — detections reason about
  connections, and it keeps event volume sane.
- **Corroboration, not attribution.** Network events establish that an edge
  exists; the detections add who traversed it and what happened next.

## Limitations

- Best-effort protocol labelling by port only (no deep packet inspection).
- Flows are aggregated in memory per run; for long live captures, window and
  flush periodically.
