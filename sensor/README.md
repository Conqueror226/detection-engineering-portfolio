# ECS Network Telemetry Sensor

A Scapy-based sensor that captures (or replays) packets, folds both directions of
a conversation into one **bidirectional flow**, and emits **ECS network events**
as NDJSON. It is a *telemetry producer only* — detection and correlation live in
`../detections` and in the edge materializer.

## Usage

```bash
# Offline replay (no privileges) — used by CI and tests
python sensor/sensor.py --pcap sensor/fixtures/lateral_movement.pcap

# Live capture (real-time via AsyncSniffer; requires root/Administrator)
sudo python sensor/sensor.py --iface eth0 --out network.ndjson --flush-interval 30
```

`--pcap FILE` | `--iface IFACE` (mutually exclusive), `--out FILE` (default stdout),
`--observer-hostname NAME`, `--flush-interval SECONDS` (live).

## Output (ECS)

One event per flow. Client/server orientation is decided by the SYN initiator, so
the ephemeral return direction can never masquerade as a new connection to a high
port. Sensor identity lives under `observer.*`, not `host.*`.

```json
{
  "@timestamp": "...",
  "ecs": { "version": "8.11.0" },
  "event": { "kind": "event", "category": ["network"], "type": ["connection"],
             "module": "network_flow", "dataset": "network_flow.flow" },
  "observer": { "hostname": "sensor-host", "type": "sensor", "product": "scapy-ecs-sensor" },
  "client": { "ip": "10.20.4.51", "port": 49712, "packets": 5, "bytes": 620 },
  "server": { "ip": "10.20.4.60", "port": 3389, "packets": 4, "bytes": 300 },
  "source": { "ip": "10.20.4.51", "port": 49712 },
  "destination": { "ip": "10.20.4.60", "port": 3389 },
  "network": { "transport": "tcp", "protocol": "rdp", "packets": 9, "bytes": 920 }
}
```

`source`/`destination` mirror `client`/`server` (orientation-stable) so downstream
consumers keep working. `network.protocol` is a best-effort label from the server
port.

## Fixtures

`fixtures/*.pcap` are synthetic, generated by `generate_fixtures.py`:

| Fixture | Scenario | Feeds |
|---|---|---|
| `lateral_movement.pcap` | one RDP (tcp/3389) connection, attacker → target | authenticated-pivot detection |
| `port_scan.pcap` | one source → 25 distinct server ports on one host | T1046 discovery detection |
| `benign.pcap` | ordinary HTTPS + DNS | negative case |
| `https_fanout.pcap` | 15 HTTPS connections to **one** server port | negative: many connections ≠ a scan |

Regenerate with `python sensor/generate_fixtures.py`.

## Design notes

- **Offline-first for testability** — pcap replay needs no privileges, so the same
  code path runs in CI; live capture uses `AsyncSniffer` with periodic flushing of
  idle flows so events stream in real time rather than only at capture end.
- **Bidirectional flows** with a canonical 5-tuple key; directional and total
  packet/byte counts are reported.
- **Corroboration, not attribution** — network events establish that an edge
  exists; identity and privilege are added downstream.
